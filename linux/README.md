# Tushare 云端持续采集器 · Ubuntu 24.04 x86_64

Windows版的独立Linux版本：保留数据目录、全量计划、历史起点核验、断点、增量更新、任务切换、归档预览和网页面板；更改为双Token协作及任务级失败隔离。数据与状态只写入本部署目录，不读写Windows采集器。

## Ubuntu服务器部署

上传本目录生成的 `数据采集器_linux_Ubuntu24_x86_64.tar.gz` 和校验文件到服务器。内含Linux可执行程序及依赖；服务器无需Docker、Python或pip安装。

```bash
sha256sum -c 数据采集器_linux_Ubuntu24_x86_64.tar.gz.sha256
sudo tar -xzf 数据采集器_linux_Ubuntu24_x86_64.tar.gz -C /opt
cd /opt/数据采集器_linux_Ubuntu24_x86_64
sudo bash scripts/install.sh
sudo bash scripts/configure.sh
sudo bash scripts/start.sh
```

配置过程交互输入主Token、备用Token，输入不回显；可仅配置一个，另一个留空。自动生成当前可建立的全量计划，独立权限接口固定排除。配置不请求数据；启动systemd服务后按计划持续采集。重复配置保留已有全量计划与归档。

当前服务按root安装，凭据和密钥目录权限700、文件600；不把任何真实凭据放入源码、压缩包或Git。首次部署后需要自行配置账号。服务端本机密钥加密保护落盘Token；密钥和数据库必须一起备份。

## 继承本机进度，云端只继续新增批次

本次部署包的 `基线/` 包含本机已提交计划、分页/日期/参数组断点、完成状态、归档校验摘要及必要的证券目录缓存。不会包含Windows账号、加密密钥、完整状态数据库或普通历史数据归档。目录缓存直接随包迁移，已经完成的证券目录不再在线获取。

导出前必须暂停Windows采集并等待当前请求结束。每个已提交归档都会校验存在性、接口、行数及SHA256；首次配置或启动时原子导入。重复启动不会重导入，也不允许用另一基线覆盖云端新进度。已经完成的项目不重拉，未完成项目从下一批精确续采。任务累计数包含本机基线，归档预览只列云端新增文件。

首次配置或更换账号只补建缺失的计划，不改写已有计划的参数、日期范围、完成状态或分页断点，也不会跨日自动延长并回查旧数据。需要扩大已有范围时，在页面明确选择更新/修订；“更新至今天”可能按原有规则回查历史，属于人工操作，不由迁移流程自动执行。

Windows的原有数据仍保存在本机，不迁移到云端数据归档目录；目录缓存明确单独保存。部署后保持Windows采集停止，避免双方从同一断点重复请求。基线快照之后若本机又继续采集，需要重新导出部署包或单独核对进度，旧快照无法知道后续新增数据。

基线只保留在本机交付目录和部署包中，绝不上传GitHub。Git仓库重建不带本机进度；可显式用 `打包.ps1 -WithoutBaseline` 构建通用无基线版本。

## 在本机浏览器查看云端面板

服务默认只监听服务器 `127.0.0.1:18794`，不必在安全组开放网页端口。在自己的Windows电脑执行：

```powershell
ssh -N -L 18794:127.0.0.1:18794 root@你的服务器IP
```

另一个SSH窗口在服务器部署目录执行 `bash scripts/access.sh`，取得完整本机访问地址，在Windows浏览器打开。地址包含访问令牌，不能公开。令牌持久化，服务重启后仍有效。

关闭网页、本机关机、SSH断开，只影响面板访问，不影响systemd采集。服务器重启自动恢复之前的运行意愿；网页手动暂停会持久化暂停。网页“安全关闭”正常退出后不会由systemd立即拉起；可通过start.sh重新启动。

## 持续采集规则

- 两个Token分别领取不同任务，同一任务始终只有一个持有者推进断点，不重复并发写同一页。
- 所有通道共享全局400/min、接口更低额度及IP冷却；两个Token不等于IP额度翻倍。
- 网络、超时、限流和临时服务故障30秒起持续重试，不受Windows版三次上限约束；较长上游等待提示优先。重试等待不阻塞其他任务。
- 无权限、参数不兼容、接口不支持时隔离当前项目，其他可执行任务继续。Token认证失败停用对应通道；两个都失效时服务保持运行、等待更换账号，不继续撞接口。
- 独立权限接口在建计划、手动计划和请求派发三处排除，不能勾选绕过。
- 目录失败时关联项目标为受阻；不相关任务继续。重新配置或修复计划后，可在暂停状态选择项目重试。
- 已完成但没有可用代码的目录不会让关联任务永远等待，而是标记依赖受阻；目录重新采集得到有效代码后，关联任务可自动恢复，并继续遵守限频。
- 目录依赖受阻与数据校验受阻分别持久化。行列、分页或历史覆盖校验失败的项目保持隔离，不会因目录完成而自动重新请求；须人工修订或选择重试。
- 网页和命令行更换Token使用同一恢复逻辑，只清除被替换通道的认证/权限拒绝记录，保留任务断点与限频冷却；未替换通道的状态不变。
- 连续空区间、无法可靠分页或不可信日期不冒充完成。空结果只保存核验状态，不写空JSON。
- 全部可执行项目完成且没有等待中的可恢复重试后进入待机，列出排除、不可用及待核验项。完成表示所选查询范围走完，不保证供应商绝对完整。不会自动每日更新；需要延长范围时在页面更新或补齐计划。

程序不能在账号全部失效、磁盘持续满或上游永久不可用时保证取得数据；这些状态会明确展示，不让一个接口的失败终止整个进程。

## 倒序历史采集

Linux版日期任务从所选截止日期向历史倒查；范围接口按最多365天请求，达到上限时沿同一区间分页，不能分页则缩小区间，上界保持不变。单日、月、季、年任务倒序推进；目录和基本资料快照仍遍历分类及分页。

已有正序任务迁移时保留已提交前缀及参数组，未完成分页先按原请求取完该区间，再切换倒序。迁移前计划和断点保存到revisions；不会重新请求本机已提交的区间。已完成项目保留完成状态。倒序尚未完成的任务需先续采原范围，完成后才可更新截止日期，避免覆盖历史断点。

空结果不落空JSON，不作为首次结束信号。未知起点连续约五年为空（范围接口5个区间、按日1826个、月60个、季20个、年5个）或整个参数组范围皆空时，标记历史覆盖待核验，其他项目继续。完成只表示所选区间已走完。已核验的接口history_start边界及已有证券目录中的上市日期（仅约束交易日期）、基金成立日期（仅约束净值日期）可作为更早边界；没有这些字段时不猜测起点，也不额外请求目录。

按日交易查询仅跳过已保存交易日历明确标记为休市的日期；日历缺失、交易所不明或没有相应日期时仍实际查询，避免把缺记录当休市。临时限流、超时等保留断点30秒起重试；参数/权限错误继续隔离，不视为空历史。
